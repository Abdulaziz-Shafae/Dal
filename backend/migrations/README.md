# إنشاء جداول المحادثة الجماعية

الإعداد الحالي `spring.jpa.hibernate.ddl-auto=update` لم يتغير. اختر طريقة إنشاء واحدة:

1. **المسار الموافق للإعداد الحالي:** عند نشر المالك للـ Backend، ينشئ Hibernate الجدولين المفقودين. لا تنفّذ ملف SQL يدويًا في هذا المسار.
2. **المسار اليدوي البديل:** أوقف Backend، وافحص وجود `group_messages` و`group_message_reads`. إذا كان كلاهما مفقودًا، نفّذ ملف SQL مرة واحدة قبل التشغيل. إذا وُجدا، لا تعِد تنفيذه؛ تحقق من المخطط. إذا وُجد أحدهما فقط، توقف للمراجعة اليدوية؛ لا تحذف الجداول تلقائيًا. بعد الإنشاء اليدوي يتعرف `update` على الجداول الموجودة.

هذا المجلد ليس ضمن موارد SQL التلقائية، ولا توجد آلية Flyway أو Liquibase تنفّذ الملف. لا تنفّذ SQL بعد إنشاء Hibernate للجداول: أوامر `CREATE TABLE` تفشل عند وجودها. عمليات DDL في MySQL تعمل بـ implicit commit، فلا تفترض إمكان التراجع عن الملف كمعاملة واحدة.

اختُبر المساران على Oracle MySQL 8.4.11 محلية منفصلة، مع إعادة التشغيل و`validate`. ظلت الأعمدة والفهارس والمفاتيح الأجنبية ثابتة، وحُفظت الرسائل ومؤشرات القراءة. لا يعني ذلك غياب جميع أوامر DDL الداخلية التي قد يصدرها Hibernate؛ النتيجة المثبتة هي عدم تكرار عناصر المخطط. قيمة SQL الافتراضية `last_message_id=0` متوافقة مع تهيئة JPA للحقل.

لإعادة الاختبار، جهّز قاعدة **فارغة وتجريبية فقط** باسم `dal_migration_qa` على MySQL في `127.0.0.1:33307`، وحسابًا باسم `dal_mysql_qa` بصلاحيات على هذه القاعدة وحدها. عيّن `DAL_RUN_MYSQL_QA=true` و`DAL_MYSQL_QA_PASSWORD` في بيئة الاختبار، ثم شغّل اختبارات Maven. الاختبار يرفض MariaDB أو قاعدة غير فارغة؛ ويحذف الجدولين فقط داخل هذه القاعدة التجريبية لإثبات مساري الإنشاء. لا تستخدم حسابات أو بيانات الإنتاج.

لم تُفحص نسخة MySQL الإنتاج أو مخططها، ولم يُنفذ أي SQL على Railway. يراجع المالك النسخة والمخطط والنسخة الاحتياطية قبل نشره بنفسه. لم تتغير إعدادات Railway أو إعدادات التطبيق.
